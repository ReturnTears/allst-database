# 07 数据备份与恢复

## 场景

备份分成两种，用途不同。

| 方式 | 做什么 | 不能做什么 |
| --- | --- | --- |
| 逻辑导出 | 按设备或指标类型把点写成 line protocol | 不能当作整库备份，有行数上限 |
| `influxd backup -portable` | 在线拷贝 shard 文件 | 应用进程默认不执行，避免误碰数据目录 |

整库恢复演练用第二种。把某个设备的一段数据挪到别的环境，用第一种。

## 逻辑导出

```bat
curl.exe -X POST "http://127.0.0.1:8091/api/influx/backup/export?deviceId=dev-001&metricType=temperature&range=6h"
```

必须带 `deviceId` 或 `metricType`。文件写到 `influx.ops.backup-dir`，默认 `./data/influx-backup`，文件名以 `.lp` 结尾。响应里有 `sha256` 和 `truncated`。`truncated=true` 表示本页已经顶到 limit，需要缩小时间范围再导。默认 5000 行，最大 20000 行，文件最大 20MB。

恢复只接受这个目录下的 `.lp`，并且每一行都必须是 `device_metric`：

```bat
curl.exe -X POST "http://127.0.0.1:8091/api/influx/backup/restore?fileName=device_metric-20261024T120000Z.lp"
```

文件名不能包含 `..` 或路径分隔符。恢复写回当前配置的库和保留策略，时间戳按纳秒解释，和导出时的 `lineProtocol(NANOSECONDS)` 一致。业务时间本身仍然是毫秒。

## 物理备份

在线备份走 `8088`，不是 `8086`。命令和脚本一致：

```bat
influxd backup -portable -database allst_iot -retention rp_raw_7d -host 127.0.0.1:8088 data\influx-backup\portable-目录
influxd restore -portable -db allst_iot -rp rp_raw_7d -newdb allst_iot_restore -host 127.0.0.1:8088 data\influx-backup\portable-目录
```

恢复必须进一个新库。脚本和接口都会拒绝 `newdb` 与当前库同名，避免把正在查询的库覆盖掉。确认新库之后，再手工决定是否替换旧库。

```bat
curl.exe -X POST "http://127.0.0.1:8091/api/influx/backup/portable?action=backup"
curl.exe -X POST "http://127.0.0.1:8091/api/influx/backup/portable?action=restore&name=portable-20261024T120000Z"
```

`influx.ops.allow-shell` 默认是 false。这时接口只返回命令，不启动 `influxd`。在数据库宿主机上执行返回的命令，或直接用脚本：

```bat
powershell -File deploy\backup\backup.ps1
set INFLUX_NEW_DATABASE=allst_iot_restore
powershell -File deploy\backup\restore.ps1 data\influx-backup\portable-目录
```

Linux 下是 `deploy/backup/backup.sh` 和 `restore.sh`。

打开 `allow-shell` 之后，接口会在应用机器上执行命令，超时 120 秒。大库备份不要走应用进程，用宿主机上的计划任务跑脚本。

## 生产环境要注意

- 物理备份要定期做恢复演练，只看备份命令的退出码不够。演练目标用 `-newdb`。
- Enterprise 还要备份 meta 节点。只有 data 备份时，集群成员关系恢复不出来。开源单节点没有单独的 meta 集群。
- 逻辑导出依赖查询，受 7 天原始保留期限制。过期的原始点导不出来，降采样结果要单独指定 measurement 做物理备份。
- 备份目录 `data/` 已经在模块的 `.gitignore` 里，不要把导出的点提交进仓库。
