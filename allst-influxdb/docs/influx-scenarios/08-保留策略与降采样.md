# 08 保留策略与降采样

## 场景

原始点保留 7 天，分钟聚合保留 90 天，小时聚合保留 365 天。过期由 InfluxDB 按 shard 删除，应用不写定时清理任务。

降采样的计算在 [04-连续查询](04-连续查询.md)。这篇只规定保留多久、shard 多大。

## 三档策略

| 名称 | 时长 | shard | 是否默认 | 里面放什么 |
| --- | --- | --- | --- | --- |
| `rp_raw_7d` | 7 天 | 1 天 | 是 | `device_metric` |
| `rp_down_90d` | 90 天 | 7 天 | 否 | `device_metric_1m` |
| `rp_down_365d` | 365 天 | 30 天 | 否 | `device_metric_1h` |

shard 必须短于保留时长。保留策略删除数据的单位是 shard，不是一个点。1 天一个 shard 时，7 天前的原始点会在那个 shard 到期后一起消失，消失时间可能比 7 天再晚一个 shard 周期。

`autogen` 是建库时的无限期默认策略。初始化会把默认策略改成 `rp_raw_7d`，再尝试删掉 `autogen`。里面已经有数据时删除会失败，这一步记成 warning，其余步骤继续。

## 代码

- `com.allst.boot.influx.schema.InfluxSchema`
- `com.allst.boot.influx.schema.SchemaService`
- `deploy/init/schema.iql`

`SchemaService` 先看策略在不在。没有就 `CREATE`，有就 `ALTER`，所以初始化可以重复执行。非默认策略先处理，最后再把 `rp_raw_7d` 设成默认，避免出现没有默认策略的空档。

副本数来自 `influx.replication-factor`。开源版保持 1。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/influx/schema/init` | 建库、策略、连续查询 |
| GET | `/api/influx/schema/retention-policies` | 当前库的策略 |
| GET | `/api/influx/schema/fields` | `device_metric` 的字段类型 |

空库也可以用 CLI 导入 `deploy/init/schema.iql`。那份文件不会把已存在的策略改成 `ALTER`，第二次导入可能失败。日常用初始化接口。

```bat
curl.exe -X POST http://127.0.0.1:8091/api/influx/schema/init
curl.exe http://127.0.0.1:8091/api/influx/schema/retention-policies
```

## 生产环境要注意

- 把默认策略从无限期改成 7 天之前，确认没有人还在往 `autogen` 写。
- 查询和删除都要带上保留策略名。只写 measurement 时，命中的是默认策略。
- 原始数据 7 天后没了。需要更长历史时读 `device_metric_1m` 或 `device_metric_1h`，并且先做一次回填。
- shard 太小会让文件数量上涨，太大则过期不及时。这里按保留时长大约切成几天到一个月一块。
