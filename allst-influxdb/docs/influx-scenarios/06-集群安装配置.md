# 06 集群安装配置

## 场景

应用只配置一个 `influx.url`。集群怎么部署，不进业务代码。读写都打这个地址，所以这个地址必须同时能写和能查。

InfluxDB 1.x 的开源版没有共识集群。数据副本只存在于 Enterprise。下面三份材料对应三种不同的部署，不要混成一种。

## 开源单节点

本地开发和单机业务用这个：

```bat
docker compose -f deploy/docker-compose.yml up -d
```

`8086` 是 HTTP，应用连它。`8088` 是在线备份端口，`influxd backup` 连它，不是给应用写数据的。

账号、库名和 `application.yml` 一致。容器第一次启动时会创建 `allst_iot` 和 `admin`，保留策略和连续查询仍要调用 `POST /api/influx/schema/init`。

## 开源双写

`deploy/cluster/docker-compose.relay.yml` 起两个互不复制的 1.8 节点，端口 `8086` 和 `8087`。这不是集群，只是两份独立数据。

[InfluxDB Relay](https://github.com/influxdata/influxdb-relay) 可以把一次写入转发到两个节点。示例在 `deploy/cluster/relay.toml`。官方没有长期维护的 relay 镜像，所以 compose 文件不启动 relay。需要时按上游仓库编译 `influx-relay`，再挂这份 toml。

Relay 只转发写入，不转发查询。本项目的客户端不能把 `influx.url` 指到 relay，否则查询接口没有数据面。用法是：

- Spring Boot 的 `influx.url` 指向其中一个节点，读写都走它
- 只写不读的采集器指向 relay，由 relay 写到两个节点

两个节点的查询结果会有延迟差。需要强一致读时，不要用这套双写。

## Enterprise 集群

Enterprise 1.x 才有 meta 节点和 data 节点。安装包不在公开的 `influxdb` 镜像里，下面的文件是配置模板，不能靠 `docker compose up` 跑起来。

| 文件 | 作用 |
| --- | --- |
| `deploy/cluster/influxdb-meta.conf` | meta 节点。奇数个，常见 3 个。`hostname` 每台不同 |
| `deploy/cluster/influxdb-data.conf` | data 节点。应用访问它的 `8086` |

加入集群的命令在配置文件注释里，使用 `influxd-ctl`：

```bat
influxd-ctl add-meta meta-2:8091
influxd-ctl add-data data-1:8088
influxd-ctl show
```

meta 示例把 HTTP 放在 `8091`，这是 Enterprise 文档里的常见端口。本模块的接口也是 `8091`，不要把 meta 节点和这个 Spring Boot 进程放在同一台机器的同一个端口上。

副本数写在保留策略上，不写在配置文件里：

```sql
CREATE RETENTION POLICY "rp_raw_7d" ON "allst_iot"
  DURATION 7d REPLICATION 2 SHARD DURATION 1d DEFAULT
```

`REPLICATION` 不能大于 data 节点数量。开源版只能是 1，大于 1 时创建保留策略会失败。本模块用 `influx.replication-factor` 控制初始化语句里的这个数字，默认 1。

一致性级别：

| 值 | 含义 |
| --- | --- |
| `ONE` | 一个 data 节点确认即可。单节点和大多数写入用它 |
| `QUORUM` | 多数副本确认 |
| `ALL` | 全部副本确认，延迟取决于最慢的节点 |
| `ANY` | 只要接到写入就算成功，节点宕机时可能丢 |

应用前面可以放负载均衡，后端是 data 节点的 `8086`。对这套代码来说，负载均衡的地址就是 `influx.url`。

## 生产环境要注意

- 先确定要的是“单地址高可用”还是“副本”。Relay 解决的是采集器双写，不是查询高可用。
- meta 节点不存业务点。备份时 meta 和 data 要分开看，见 [07-数据备份与恢复](07-数据备份与恢复.md)。
- 2.x 开源版同样是单节点。集群能力在 InfluxDB Enterprise 2 和 InfluxDB 3 Clustered，接口已经不是 InfluxQL。
