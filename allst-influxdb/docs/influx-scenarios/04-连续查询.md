# 04 连续查询

## 场景

原始点保留 7 天。超过 7 天还要看趋势时，靠连续查询把 1 分钟和 1 小时的聚合写到更长的保留策略里。查询历史趋势时读聚合 measurement，不读原始点。

连续查询在服务端按间隔执行。它覆盖的是“从现在往前一个窗口”，不会自动补上创建之前的历史。历史用回填接口补一次。

## 两条查询

`cq_device_metric_1m`，每分钟执行，重算最近 5 分钟，写入 `rp_down_90d.device_metric_1m`：

```sql
CREATE CONTINUOUS QUERY "cq_device_metric_1m" ON "allst_iot"
RESAMPLE EVERY 1m FOR 5m
BEGIN
  SELECT mean("value") AS "value", max("value") AS "max_value",
         min("value") AS "min_value", count("value") AS "sample_count"
  INTO "rp_down_90d"."device_metric_1m"
  FROM "rp_raw_7d"."device_metric"
  GROUP BY time(1m), *
END
```

`cq_device_metric_1h` 用同样的字段，`EVERY 1h FOR 2h`，`GROUP BY time(1h)`，写入 `rp_down_365d.device_metric_1h`。小时聚合直接读原始点，避免“均值的均值”。代价是每小时扫一次原始 measurement。原始点只有 7 天，扫的范围有限。

`RESAMPLE FOR` 比间隔更长，是为了迟到的点。5 分钟内到达的数据会重算对应的分钟桶。相同 series 和时间戳再次写入会覆盖，不会加两次。

`GROUP BY *` 会带上全部 tag。所以原始 measurement 上不能出现追踪号这种 tag，否则降采样的 series 会一样多。

## 代码

- `com.allst.boot.cq.ContinuousQueryService`
- `com.allst.boot.influx.sql.SchemaStatements`
- `deploy/init/schema.iql` 与上面的语句保持一致，测试会检查这份文件

`POST /api/influx/schema/init` 会一并创建这两条查询。已经存在的不会重建。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/influx/continuous-queries` | 只返回当前库的查询 |
| POST | `/api/influx/continuous-queries/init` | 缺哪条补哪条 |
| POST | `/api/influx/continuous-queries/backfill?level=1m&range=6h` | 用 `SELECT INTO` 补历史。`level` 只允许 `1m` 或 `1h` |
| DELETE | `/api/influx/continuous-queries/{name}` | 只允许删 `cq_` 开头的名字 |

回填的结束时间必须早于当前还没走完的窗口，避免和连续查询同时写这一分钟。`range=6h` 会自动把结束时间放在 `now - 1m` 或 `now - 1h`。

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:8091/api/influx/schema/init
curl.exe -X POST http://127.0.0.1:8091/api/influx/metrics/seed
curl.exe -X POST "http://127.0.0.1:8091/api/influx/continuous-queries/backfill?level=1m&range=2h"
curl.exe http://127.0.0.1:8091/api/influx/continuous-queries
```

样例数据是最近 60 个整分钟，`range=2h` 的回填能覆盖它们。只调用 seed、不回填时，要等下一分钟连续查询才会写出聚合点。

## 生产环境要注意

- 改聚合字段要新建查询名和目标 measurement。覆盖旧查询前，先确认没有任务还在读旧字段。
- `INTO` 的保留策略必须先存在。初始化顺序是库、保留策略、连续查询。
- 服务端调度间隔在 `deploy/influxdb.conf` 的 `[continuous_queries] run-interval`。它决定多久检查一次，不决定桶的大小。
- 2.x 没有 Continuous Query。对应能力是 Task，不在这个客户端里。
