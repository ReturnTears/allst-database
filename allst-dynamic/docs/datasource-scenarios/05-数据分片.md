# 数据分片

事件按分片键落到 16 个槽，槽再指向数据源。分片键的算法不变，扩容时只把一部分槽改到新库。这和 [02-分库分表](02-分库分表.md) 的差别是：分库分表的库表在代码里算死；这里的槽位目录可以在运行中修改。

每个分片库一张 `t_event`，不再拆表。

## 初始目录

| 槽 | 数据源 | 库 |
| --- | --- | --- |
| 偶数 0,2,...,14 | `dataShard0` | `dyn_shard_0` |
| 奇数 1,3,...,15 | `dataShard1` | `dyn_shard_1` |

```
slot = floorMod(shardKey.hashCode(), 16)
```

同一个分片键每次得到同一个槽，直到这个槽被迁走。

## 代码

- `ShardDirectory`：槽位数组，`move` 只改指向
- `ShardEventService`：按分片键选库后读写 `t_event`
- 新分片库走 `RuntimeDataSourceService`，键名是 `rtShard` 加名称，同样不能带下划线

迁槽不会搬历史数据。演示里把槽指到另一台已经有表的库，新写入会到新库，旧行仍留在原库。生产迁移要先复制数据，再切换槽位，最后核对行数。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/scenario/shard/locate?shardKey=` | 槽位和数据源，不访问数据库 |
| GET | `/scenario/shard/directory` | 16 个槽的当前指向 |
| POST | `/scenario/shard/events` | 写入该键所在的分片 |
| GET | `/scenario/shard/events?shardKey=` | 只查这个键所在的库 |
| POST | `/scenario/shard/datasources` | 注册新的分片库 |
| POST | `/scenario/shard/slots` | 把列出的槽指到一个已存在的数据源 |

```bat
curl.exe "http://127.0.0.1:8000/dynamic/scenario/shard/locate?shardKey=device-7"
curl.exe -X POST http://127.0.0.1:8000/dynamic/scenario/shard/events -H "Content-Type: application/json" -d "{\"shardKey\":\"device-7\",\"eventType\":\"online\",\"payload\":\"up\"}"
curl.exe "http://127.0.0.1:8000/dynamic/scenario/shard/events?shardKey=device-7"
curl.exe -X POST http://127.0.0.1:8000/dynamic/scenario/shard/slots -H "Content-Type: application/json" -d "{\"dataSource\":\"dataShard0\",\"slots\":[0,2,4]}"
```

`slots` 只能是 0 到 15。`dataSource` 必须已经注册，不能指向一个不存在的键。

## 注意

1. 槽位目录目前在内存里，重启后回到偶数 `dataShard0`、奇数 `dataShard1`。生产环境把目录放到独立的配置库或配置中心，应用启动时加载。
2. 查询必须带分片键。没有分片键就只能扫全部槽，和分库分表的散查一样，不能当普通列表接口。
3. 调整槽位和复制数据不是同一步。只改目录会让新旧数据分居两个库。
