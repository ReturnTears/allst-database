# 01 基本写入

## 场景

设备上报一条遥测，接口返回时协调节点已经确认。同一台设备、同一个指标、同一个毫秒、同一个 `readingId` 再写一次，后一次覆盖前一次。Cassandra 的 `INSERT` 就是 upsert，没有单独的 update。

原始数据进 `allst_iot.sensor_reading`。按区域查的数据同时进 `allst_iot.reading_by_region`。字段和主键见 [08-数据模型规范](08-数据模型规范.md)。

## 同步、批量和异步

| 方式 | 接口 | 什么时候返回 |
| --- | --- | --- |
| 同步 | `POST /api/cassandra/readings` | 两张表都得到协调节点确认 |
| 批量 | `POST /api/cassandra/readings/batch` | 按分区分组，每组一个 `UNLOGGED` 批次，全部确认后返回 |
| 异步 | `POST /api/cassandra/readings/async` | 请求已经交给驱动，协调节点还没确认 |
| 样例 | `POST /api/cassandra/readings/seed` | 3 台设备、3 个指标、最近 60 个整分钟，共 540 行 |

批量只把**同一个分区**的行放进一个 `UNLOGGED BATCH`，每批最多 50 行。设备和区域是两套分区，所以分成两次写，不放进一个跨分区的 `LOGGED BATCH`。

`readingId` 可以不传。不传时用设备、日桶、指标和毫秒时间生成 UUID，同一次上报重试会覆盖同一行。不要用 `now()` 当主键，协调节点每次都会给一个新的 timeuuid，超时重试会写成两行。

可选字段用 `unset`。`status` 或 `tags` 不传时，不会绑定 null，也就不会为这一格写墓碑。

`deviceModel` 是 static 列，单独一条语句写入，不和带 TTL 的遥测放在同一条 `INSERT` 里。`USING TTL` 会作用在这条语句写出的每一格上，混在一起会把设备型号提前过期。

## 代码

- `com.allst.boot.reading.ReadingWriteService`
- `com.allst.boot.reading.ReadingRules`
- `com.allst.boot.reading.SeedPlan`
- `com.allst.boot.cassandra.cql.Statements`

单次批量最多 200 行。时间不能超前 5 分钟，也不能早于 7 天。表的默认 TTL 是 7 天，更早的数据写进去也会很快过期。`ttlSeconds` 要传的话，范围是 1 到 2592000。0 会取消这一行的表级 TTL，接口直接拒绝。

`metricType` 只允许 `temperature`、`humidity`、`voltage`。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/cassandra/readings` | 写一行，并双写区域表 |
| POST | `/api/cassandra/readings/batch` | 请求体是 `{"readings":[...]}` |
| POST | `/api/cassandra/readings/async` | 提交后立即返回，`confirmed` 为 false |
| POST | `/api/cassandra/readings/seed` | 写 540 行样例 |

## 调用示例

先建表，再写样例，再写一行：

```bat
curl.exe -X POST http://127.0.0.1:8100/api/cassandra/schema/init
curl.exe -X POST http://127.0.0.1:8100/api/cassandra/readings/seed
curl.exe -X POST http://127.0.0.1:8100/api/cassandra/readings -H "Content-Type: application/json" -d "{\"deviceId\":\"dev-001\",\"region\":\"cn-east\",\"metricType\":\"temperature\",\"value\":26.5,\"status\":1}"
```

同一分钟内重复调用 `/seed` 会覆盖这 540 行，不会越积越多。换一分钟再调用，会多出新的时间戳。

`day` 按 `Asia/Shanghai` 计算。写入和查询必须用同一个时区，否则同一条数据会落到两个日桶里，查询就像丢了。

## 生产环境要注意

- 要确认的业务用同步写。异步写只适合允许丢最后几毫秒的采集，失败记在日志里，调用方看不到。
- 双写没有跨分区事务。第一张表成功、第二张表失败时，整次请求重试是安全的，因为主键相同会覆盖。
- 不要把遥测写进订单事务里一起提交。Cassandra 写失败不应该回滚订单库。
- 时间用毫秒。服务端会把传入时间截断到毫秒再生成 `readingId`。
