# 02 基本查询

## 场景

页面要看一台设备某一天的温度。查询必须带 `deviceId` 和 `day`，这是分区键。要看时间范围或只要最新一条，还要带 `metricType`，因为它是第一个聚簇列。

不带分区键的查询，这个接口不提供。也不拼 `ALLOW FILTERING`。按区域查走双写表 `reading_by_region`，不在原表上过滤 `region`。

## 分区和聚簇

`sensor_reading` 的主键是：

```text
((device_id, day_bucket), metric_type, recorded_at, reading_id)
```

`recorded_at` 倒序。同一个指标里，第一行就是最新的一行，所以 `LIMIT 1` 不用再排序。

| 查询 | 条件 |
| --- | --- |
| 这一天的全部指标 | `deviceId` + `day` |
| 一个指标 | 再加 `metricType` |
| 时间范围 | 再加 `from`、`to`。右开区间，并且必须落在这个 `day` 里 |
| 从旧到新 | `order=asc`，并且必须带 `metricType` |
| 每个指标的最新值 | `GROUP BY metric_type`，返回每个组的第一行 |

跨过午夜要查两天，就请求两次。一条查询不跨日桶。

## 代码

- `com.allst.boot.reading.ReadingQueryService`
- `com.allst.boot.reading.DayBuckets`
- `com.allst.boot.cassandra.cql.Statements`

`from`、`to` 用 `2026-10-24T00:00:00Z` 或 `2026-10-24 08:00:00`。没有字母 `T` 的时间按上海时区解释。

默认 100 行，最多 500 行。结果里的 `truncated=true` 表示刚好顶到 limit，后面可能还有数据。连续把后面的数据取完用 [04-连续查询](04-连续查询.md) 的 `pagingState`，不要把 limit 放到很大。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/cassandra/readings` | 一个分区，或其中一个指标 |
| GET | `/api/cassandra/readings/latest` | 一个指标的最新行 |
| GET | `/api/cassandra/readings/latest-per-metric` | 每个指标的最新行 |
| GET | `/api/cassandra/readings/by-region` | 区域表 |

## 调用示例

`day` 换成 `/seed` 实际写入的日期。样例的时间是最近 60 分钟，日桶是上海时区的今天，跨过零点时会有昨天。

```bat
curl.exe "http://127.0.0.1:8100/api/cassandra/readings/latest?deviceId=dev-001&day=2026-10-24&metricType=temperature"
curl.exe "http://127.0.0.1:8100/api/cassandra/readings?deviceId=dev-001&day=2026-10-24&metricType=temperature&limit=20"
curl.exe "http://127.0.0.1:8100/api/cassandra/readings/latest-per-metric?deviceId=dev-001&day=2026-10-24"
curl.exe "http://127.0.0.1:8100/api/cassandra/readings/by-region?region=cn-east&day=2026-10-24&metricType=temperature&limit=20"
```

时间范围：

```bat
curl.exe "http://127.0.0.1:8100/api/cassandra/readings?deviceId=dev-001&day=2026-10-24&metricType=temperature&from=2026-10-24 08:00:00&to=2026-10-24 09:00:00"
```

## 生产环境要注意

- `IN` 一次打多个分区，协调节点要分别问过去。这个接口不开放 `IN`。
- `ORDER BY` 只能沿着聚簇列的定义顺序，或者整段反过来。不能按 `sensor_value` 排序。
- 区域表和原表是双写，短暂不一致是正常的。要强一致就不要用 Cassandra 做这个查询。
- 只 SELECT 需要的列。这里没有 `SELECT *`。
