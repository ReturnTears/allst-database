# 11 删除与墓碑

## 场景

Cassandra 的删除是再写一笔“这格数据已经无效”。这笔记录叫墓碑。磁盘要等 `gc_grace_seconds` 过去，并且压缩真的处理了这个分区，空间才会回来。本模块的时序表把 `gc_grace_seconds` 设成 86400 秒。

`GET /api/cassandra/governance/advice` 返回这组约束，不连接数据库。

## 三种删除

| 方式 | 接口 | 墓碑 |
| --- | --- | --- |
| 删一行 | `DELETE /readings/row` | 这一行。传了 `region` 时，区域表上主键齐全的那一行一起删 |
| 删一个指标的一段时间 | `DELETE /readings/range` | `sensor_reading` 上的范围墓碑 |
| 删掉一台设备的一天 | `DELETE /readings/partition` | 一个分区墓碑，比循环删每一行便宜 |

范围是右开区间，`from` 和 `to` 都要落在 `day` 里面。

区域表的聚簇顺序是 `metric_type, recorded_at, device_id, reading_id`。`recorded_at` 一旦写成范围，后面的 `device_id` 就不能再限制。所以按一台设备删一段时间时，区域表删不干净，只能等同样的 7 天 TTL。单行删除因为每一列主键都有值，两张表可以一起删。

## 还有哪些写法会制造墓碑

- 绑定 null。可选列用 `unset`，这条写入不碰那一列。
- 表级 TTL 到期。每一格过期也是墓碑。时序表用按天的 `TimeWindowCompactionStrategy`，过期的一天可以整窗丢掉，比一行行删便宜。
- 把 Cassandra 当队列，只删分区的开头。墓碑会堆在仍然要读的那一段聚簇上。

`tombstone_warn_threshold` 默认 1000。一个分区的一次读如果碰到这么多墓碑，日志里会报警，延迟也会上去。再多到失败阈值，查询直接被拒绝。

## 代码

- `com.allst.boot.governance.GovernanceService`
- `com.allst.boot.governance.GovernanceNotes`

删除语句标记为幂等。同一行再删一次，结果还是没有这行。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/cassandra/governance/advice` | 约束说明 |
| DELETE | `/api/cassandra/governance/readings/row` | 删一行 |
| DELETE | `/api/cassandra/governance/readings/range` | 范围删除 |
| DELETE | `/api/cassandra/governance/readings/partition` | 删掉一个设备日分区 |

## 调用示例

```bat
curl.exe http://127.0.0.1:8100/api/cassandra/governance/advice
curl.exe -X DELETE "http://127.0.0.1:8100/api/cassandra/governance/readings/partition?deviceId=dev-003&day=2026-10-24"
```

删一行时带上区域，两张表一起删：

```bat
curl.exe -X DELETE "http://127.0.0.1:8100/api/cassandra/governance/readings/row?deviceId=dev-001&day=2026-10-24&metricType=temperature&time=2026-10-24T04:00:00Z&readingId=替换成实际的UUID&region=cn-east"
```

## 生产环境要注意

- 多副本时，墓碑要先复制到其他副本，`gc_grace_seconds` 才可以到点清理。在 repair 之前把它改成 0，没收到删除的副本会把旧数据送回来。单节点 RF 1 没有第二份副本，演示才比较安全。
- 大批量删除放在低峰，并预期随后的读会变慢。能靠 TTL 和 TWCS 过期的数据，就不要先查出来再逐行删。
- 删除和插入如果时钟差很多，旧的写入可能盖过新的墓碑，或者相反。机器要做时间同步。`writetime` 可以用来核对。
- 计数器表不要用这里的删除接口去“清零”。清零不是把计数器设成 0，语义也不一样。
