# 07 数据备份与恢复

## 场景

Cassandra 的备份是节点上的 SSTable 快照，不是一条 SQL dump。`nodetool snapshot` 给当前的 SSTable 做硬链接，文件还在同一块磁盘上。拷到别的机器或对象存储之后，才算备份完成。

这个模块做两件事：

- `GET /api/cassandra/backup/plan` 返回快照、清理和 refresh 的命令，不在应用进程里执行
- `POST /export` 和 `POST /restore` 导出、导回**一个分区**的逻辑数据，方便查某一台设备某一天

逻辑导出不能代替快照。它没有墓碑，恢复时用的是现在的写入时间，表级 TTL 从恢复这一刻重新算。

## 快照

```text
nodetool snapshot allst_iot -t allst-20261024
nodetool listsnapshots
```

快照目录在数据目录的 `allst_iot/<表>-<uuid>/snapshots/<tag>/`。把这个目录拷走。确认拷贝完成再清理：

```text
nodetool clearsnapshot -t allst-20261024 allst_iot
```

增量备份在 `cassandra.yaml` 里把 `incremental_backups` 设为 true。之后每次 flush 会在 `backups/` 里再留一份硬链接。它只包含打开之后的新文件，第一次仍然要做全量快照。硬链接同样占的是同一块盘，磁盘坏了两份一起没。

`/plan` 里的 `nodetool refresh` 是恢复时用的，不是备份时用的。

## 恢复

恢复到原来的节点：

1. `nodetool drain`，再停进程。drain 会把内存里的数据刷出去，并停掉新的写入。
2. 把快照里的 SSTable 放回对应表的数据目录，不要放进 `snapshots/` 子目录。
3. 启动节点，执行 `nodetool refresh allst_iot sensor_reading`。

恢复到别的集群或别的节点，用 `sstableloader`，把快照目录传给它，让它按 token 把文件流到该去的节点。不要复制 `system`、`system_schema` 这些系统 keyspace。

生产上可以把调度、上传和校验交给 [Medusa](https://github.com/thelastpickle/cassandra-medusa)。本模块不包装它的命令。

## 逻辑导出

导出要求 `deviceId` 和 `day`，也就是一个分区。默认 1000 行，最多 5000 行，文件最大 20MB。文件在 `./data/cassandra-backup`，名字以 `.jsonl` 结尾。

每一行是一个 JSON 对象，字段和写入接口一致。恢复时重新走插入和区域表双写，所以主键相同的行会被覆盖。

## 代码

- `com.allst.boot.ops.BackupService`
- `com.allst.boot.ops.BackupCommands`
- `com.allst.boot.ops.BackupPaths`

文件名不允许 `..`。快照名只允许字母、数字、下划线和中划线。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/cassandra/backup/plan` | 快照命令。`tag` 可选 |
| POST | `/api/cassandra/backup/export` | 导出一个分区 |
| POST | `/api/cassandra/backup/restore` | 按文件名导回 |

## 调用示例

```bat
curl.exe "http://127.0.0.1:8100/api/cassandra/backup/plan?tag=allst-20261024"
curl.exe -X POST "http://127.0.0.1:8100/api/cassandra/backup/export?deviceId=dev-001&day=2026-10-24&metricType=temperature"
curl.exe -X POST "http://127.0.0.1:8100/api/cassandra/backup/restore?fileName=sensor-reading-20261024T000000Z.jsonl"
```

`fileName` 用导出响应里的名字。

## 生产环境要注意

- 快照期间节点还在服务。硬链接本身很快，拷贝文件才占磁盘和时间。
- 不要在业务低峰之外对所有节点同时做快照又同时压缩。磁盘带宽会打满。
- commitlog 用来宕机恢复，不是用来回到昨天。CDC 也不是备份。
- 恢复演练要定期做。只生成快照、从来没导回过的备份，不算能恢复。
- 逻辑恢复之后，用 [03-函数与运算](03-函数与运算.md) 的 `writetime` 可以看出来这些行是刚写上去的。
