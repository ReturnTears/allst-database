# 06 集群安装配置

## 场景

本地先跑一个节点，把接口跑通。要看副本、机架和 `nodetool status` 时，再用三节点 compose。应用通过 `contact-points` 和 `local-datacenter` 连接，keyspace 的副本策略跟节点数走。

Cassandra 4.1 的服务进程使用镜像里的 Java 11。这个 Spring Boot 应用是 Java 17，两者不要混成一个 JDK 要求。

## 单节点

在 `allst-cassandra` 目录：

```bat
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml exec cassandra nodetool status
```

`nodetool status` 里这一台应该是 `UN`。`UN` 是 Up 和 Normal。

镜像是 `cassandra:4.1`。环境变量：

| 变量 | 值 | 作用 |
| --- | --- | --- |
| `CASSANDRA_CLUSTER_NAME` | `allst-cassandra` | 集群名。节点不一致就加不进来 |
| `CASSANDRA_DC` | `datacenter1` | 和 `cassandra.local-datacenter` 相同 |
| `CASSANDRA_RACK` | `rack1` | 单节点一个机架 |
| `CASSANDRA_ENDPOINT_SNITCH` | `GossipingPropertyFileSnitch` | 用上面的 DC 和机架，不要用 `SimpleSnitch` 上生产 |
| `CASSANDRA_NUM_TOKENS` | `16` | 虚拟节点。4.x 的常见默认是 16 |
| `MAX_HEAP_SIZE` | `512M` | 演示够用。生产按机器内存单独算，不要沿用 512M |

端口：`9042` 是 CQL。`7000` 是节点间通信，`7001` 是加密的节点间通信，`7199` 是 JMX。演示只把 `9042` 映射出来。

应用配置：

```yaml
cassandra:
  contact-points: 127.0.0.1:9042
  local-datacenter: datacenter1
  keyspace: allst_iot
  replication:
    strategy: SimpleStrategy
    factor: 1
```

单节点 RF 必须是 1。RF 3 又只有一台机器时，`LOCAL_QUORUM` 写不进去。

## 三节点

```bat
docker compose -f deploy/cluster/docker-compose.yml up -d
docker compose -f deploy/cluster/docker-compose.yml exec cassandra-1 nodetool status
```

不要和单节点 compose 同时开，`9042` 会冲突。三个节点的种子都是 `cassandra-1`，机架分别是 `rack1`、`rack2`、`rack3`，方便以后按机架放副本。Docker Desktop 建议至少 4GB 内存。

三台都是 `UN` 之后，副本策略改成：

```yaml
cassandra:
  contact-points: cassandra-1:9042,cassandra-2:9042,cassandra-3:9042
  local-datacenter: datacenter1
  replication:
    strategy: NetworkTopologyStrategy
    datacenters:
      datacenter1: 3
```

`GET /api/cassandra/schema/replication` 会给出对应的 `CREATE KEYSPACE` 和 `ALTER KEYSPACE`。`schema/init` 只执行 `CREATE KEYSPACE IF NOT EXISTS`，不会改已经存在的 keyspace。改副本数要自己执行 alter，然后在每个节点跑 `nodetool repair`。

宿主机上的 Java 驱动连 `127.0.0.1:9042` 时，只能稳定打到映射出来的那一台。驱动从系统表里看到的另外两台是容器 IP，宿主机不一定路由得到。看集群用容器里的 `nodetool`。应用要连全部节点，就把应用放进 compose 网络，联系点用服务名。

## 不用 Docker 时

1. 从 [cassandra.apache.org/download](https://cassandra.apache.org/download/) 下载 4.1 的 tar.gz。
2. 解压后：
   - `bin`：`cassandra` 启动进程，`cqlsh` 执行 CQL，`nodetool` 管节点，`sstableloader` 加载 SSTable
   - `conf`：`cassandra.yaml`、`cassandra-rackdc.properties`、`cassandra-env.sh`
   - `tools`：维护工具
3. `conf/cassandra.yaml` 里至少对齐这些项：`cluster_name`、`seeds`、`listen_address`、`rpc_address`、`endpoint_snitch`、`num_tokens`。
4. `conf/cassandra-rackdc.properties` 写 `dc=datacenter1` 和 `rack=rack1`。
5. 各台机器的时钟用 NTP 对齐。轻量事务和 `writetime` 都依赖时钟。

## 认证

演示镜像使用 `AllowAllAuthenticator`，所以应用默认不填密码。生产在 `cassandra.yaml` 里改为：

```yaml
authenticator: PasswordAuthenticator
authorizer: CassandraAuthorizer
role_manager: CassandraRoleManager
```

默认超级用户是 `cassandra` / `cassandra`。起来之后立刻建自己的用户，再把默认用户的口令换掉，并按 keyspace 授权。应用用环境变量 `CASSANDRA_USERNAME`、`CASSANDRA_PASSWORD`，不要写进仓库。

## 代码

- `deploy/docker-compose.yml`
- `deploy/cluster/docker-compose.yml`
- `com.allst.boot.cassandra.config.CassandraProperties`
- `com.allst.boot.cassandra.client.CqlGateway`

`CqlGateway` 使用 `DefaultLoadBalancingPolicy`，只把 `local-datacenter` 里的节点当成本地副本。这个值配错，表现就是没有可用节点。

## 生产环境要注意

- 生产不用 `SimpleStrategy`。加机房时它不会按机房放副本。
- 种子节点只是加入集群时的联系人，不要把三台都写成种子，也不要让种子全在同一个机架。
- 改 `num_tokens` 等于重新分配数据，不是改完重启就行。
- keyspace 建错了，这个接口不提供 `DROP KEYSPACE`。要推倒重来，在 `cqlsh` 里自己删。
