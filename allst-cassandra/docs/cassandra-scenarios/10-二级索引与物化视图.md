# 10 二级索引与物化视图

## 场景

主查询靠主键。还有两种查询主键覆盖不了：

- 在一台设备的一天里，只看 `status = 1` 的行
- 不带设备号，看某个指标这一天的数据

第一种用普通二级索引。第二种用物化视图 `reading_by_metric`。按区域查不走索引，走 [01-基本写入](01-基本写入.md) 的双写表。双写的失败可以在应用里重试；视图的维护在服务端，应用看不到每一行何时跟上。

## 二级索引

`schema/init` 执行：

```cql
CREATE INDEX IF NOT EXISTS sensor_reading_status_idx ON allst_iot.sensor_reading (status);
```

查询仍然带完整分区键：

```cql
SELECT ... FROM sensor_reading
WHERE device_id = ? AND day_bucket = ? AND status = ?
```

没有这个索引时，Cassandra 会拒绝查询，并提示 `ALLOW FILTERING`。这个接口不加那三个词。过滤应该发生在一个分区内部，而不是让协调节点把所有分区都看一遍。

`status` 只有 0 到 9，基数很低，索引切片可能很大。它可以缩小一个分区里的结果，不适合当成“按状态找全库设备”的入口。高基数列，比如 `reading_id`，也不建索引。

Cassandra 4.1 没有把 Storage-Attached Index 作为可用的索引实现。`USING 'StorageAttachedIndex'` 是 5.0 的语法，在 4.1 上建表会失败，所以这里不生成它。SASI 仍然是实验索引，这个模块不创建。

## 物化视图

```cql
CREATE MATERIALIZED VIEW IF NOT EXISTS allst_iot.reading_by_metric AS
  SELECT device_id, day_bucket, metric_type, recorded_at, reading_id, region, sensor_value, status
  FROM allst_iot.sensor_reading
  WHERE device_id IS NOT NULL AND day_bucket IS NOT NULL AND metric_type IS NOT NULL
    AND recorded_at IS NOT NULL AND reading_id IS NOT NULL
  PRIMARY KEY ((metric_type, day_bucket), recorded_at, device_id, reading_id)
  WITH CLUSTERING ORDER BY (recorded_at DESC, device_id ASC, reading_id ASC);
```

视图的主键必须包含基表的全部主键列。这里只是把 `metric_type` 和 `day_bucket` 换成了分区键，没有额外再塞一个非主键列进分区键。基表每次写入，服务端还要写视图，写入会被放大。视图和基表是最终一致的，刚写完的行可能暂时查不到。

视图不能建在计数器表上，也不能包含 static 列，所以 `device_model` 和 `tags` 不在视图里。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/cassandra/indexes` | `system_schema.indexes` 和 `system_schema.views` |
| GET | `/api/cassandra/indexes/by-status` | 分区内按 status 查 |
| GET | `/api/cassandra/indexes/by-metric` | 查物化视图 |

## 调用示例

```bat
curl.exe http://127.0.0.1:8100/api/cassandra/indexes
curl.exe "http://127.0.0.1:8100/api/cassandra/indexes/by-status?deviceId=dev-001&day=2026-10-24&status=1&limit=20"
curl.exe "http://127.0.0.1:8100/api/cassandra/indexes/by-metric?metricType=temperature&day=2026-10-24&limit=20"
```

要先 `schema/init`，再 `readings/seed`。索引是异步构建的，空表上很快；已有大量数据时，创建索引期间节点会忙一段时间。

## 生产环境要注意

- 能用双写解决的查询，优先双写。写入路径在自己的代码里，失败可以重试。
- 物化视图要算进写入放大和修复成本。基表修复时视图也要一致。
- 不要为了少建一张表就在查询末尾加 `ALLOW FILTERING`。
- 索引建在低基数列上时，限制必须仍然落在一个分区里，并且要有 limit。
