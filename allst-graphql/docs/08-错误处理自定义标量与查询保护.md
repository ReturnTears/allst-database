# 08 错误、自定义标量与查询保护

## 错误形状

业务异常是 `ApiException`。`GraphqlExceptionResolver` 把它转成 GraphQL error：

```json
{
  "data": null,
  "errors": [
    {
      "message": "商品不存在",
      "extensions": { "code": "NOT_FOUND" }
    }
  ]
}
```

| code | 何时出现 |
| --- | --- |
| `NOT_FOUND` | id 或订单号没有对应记录 |
| `VALIDATION` | 入参格式不对，或分类被挂到自己下面 |
| `CONFLICT` | 唯一约束、库存不足、仍被引用就删除、乐观锁冲突 |
| `ILLEGAL_STATE` | 下架商品下单、状态跳跃、删除最后一条地址、删除未取消的订单 |
| `INTERNAL` | 未预期的异常。日志里有堆栈，响应里只有这一句「服务器内部错误」 |

乐观锁异常和数据库约束异常即使 Service 没有亲手包装，解析器也会收成 `CONFLICT`。

前端 `frontend/src/api/graphql.js` 在 `errors` 非空时抛出，`message` 直接显示在柜台顶部的红条里。

## 标量

`GraphqlScalars` 注册两个标量：

- `DateTime`：Java `LocalDateTime`，序列化成 `2026-10-24T21:00:00`。写入时会截到秒。
- `BigDecimal`：序列化用 `toPlainString()`，避免科学计数法。

注册方式是 `RuntimeWiringConfigurer`，名字必须和 Schema 里的 `scalar` 一致。

## 查询保护

`MaxQueryDepthInstrumentation(15)` 和 `MaxQueryComplexityInstrumentation(5000)` 加在 `GraphQL.Builder` 上。Spring GraphQL 默认还会装 DataLoader 的调度器；自定义 instrumentation 会把它盖掉，所以 `GraphqlRuntimeConfig` 把 `DataLoaderDispatcherInstrumentation` 放回同一条链。少了这一环，`@BatchMapping` 不会执行。

`MallGraphqlTest.deepQueryIsRejected` 用 20 层 `children` 确认深度限制生效。
