# 09 订阅

订单状态在事务提交之后发到 `OrderEventBus`。总线是 Reactor 的多播 Sink。没有订阅者时事件直接丢掉，也不回放订阅之前的变更。

```graphql
subscription {
  orderStatusChanged(orderId: "1") {
    orderNo
    status
    totalAmount
  }
}
```

`orderId` 可以省略，这时每张订单的变化都会推送。实现在 `OrderGraphqlController.orderStatusChanged`，返回 `Flux<OrderView>`。

WebSocket 路径与 HTTP 相同，都是 `/graphql`，依赖 `spring-boot-starter-websocket`。GraphiQL（`http://localhost:8089/graphiql`）可以直接开一个订阅，再在另一个标签页执行 `updateOrderStatus` 或在柜台里点「标记已支付」。

柜台本身不用 WebSocket。它在变更成功后重新查询列表。订阅留给需要长连接的调用方，避免为了演示再引入 graphql-ws 客户端。

事件在 `AfterCommit` 里发送。下单或改状态如果回滚，订阅方什么都收不到。集成测试 `orderDeductsStockAndCancelRestoresIt` 会先订阅，再取消订单，并断言收到的状态是 `CANCELLED`。
