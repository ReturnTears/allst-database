# 03 持久化建模

库表由 JPA 在启动时按实体生成。默认数据源是 H2：

`jdbc:h2:mem:mall`，控制台 `http://localhost:8089/h2`，用户 `sa`，密码为空。

## 关系

```
Customer 1 ── * Address
Category 1 ── * Category        自关联，parent_id 可空
Category 1 ── * Product
Customer 1 ── * MallOrder
MallOrder 1 ── * OrderItem * ── 1 Product
```

订单表名叫 `mall_order`。`order` 是 SQL 保留字，不能拿来做表名。

客户聚合只包含地址。订单单独成聚合，通过 `customer_id` 指向客户，客户实体上不放订单集合，避免一次加载整棵对象图。

## 快照

`OrderItem` 记下当时的 `productName`、`price`、`amount`。`MallOrder` 记下当时的收货人、电话和地址全文。之后改商品价格或改地址，历史订单不变。

## 约束

- 客户邮箱唯一，分类名称唯一。
- `Product.version`、`MallOrder.version` 是乐观锁。并发改库存或改状态时，后写入的一方得到 `CONFLICT`。
- 有订单的客户不能删除。有商品或下级的分类不能删除。被订单明细引用的商品不能删除，取消订单也不会清掉明细。
- 只有状态为 `CANCELLED` 的订单可以物理删除。
- 每个客户至少保留一条地址。

金额列是 `decimal(12,2)`。状态枚举以字符串入库（`ON_SALE`、`CREATED`），不存序号。

## 样例数据

`MallDataInitializer` 在非 `test` 环境下、客户表为空时写入：

- 分类：茶饮、器物，以及器物下面的杯盏
- 商品：明前龙井、武夷岩茶、青瓷主人杯、锤纹铜壶（铜壶为下架）
- 客户：林夏、周衡，各有一条默认地址
- 一张已支付订单：林夏购买明前龙井 2 件。下单时库存是 40，扣减后是 38

测试使用 profile `test`，独立内存库，不跑这段初始化。

## 换到 MySQL

默认不引入 MySQL 驱动。需要时在 `pom.xml` 加上 `mysql:mysql-connector-java:8.0.28`，并增加一份 profile 配置：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/allst_graphql?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: root
    password: root
    driver-class-name: com.mysql.cj.jdbc.Driver
  jpa:
    hibernate:
      ddl-auto: update
    properties:
      hibernate.dialect: org.hibernate.dialect.MySQL8Dialect
```

启动参数 `--spring.profiles.active=mysql`。表结构仍由实体生成，样例数据的判断条件不变。
