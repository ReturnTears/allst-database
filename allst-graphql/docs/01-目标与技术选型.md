# 01 目标与技术选型

## 要规范的事情

Spring Boot 项目里使用 GraphQL 时，固定下面几件事，避免每个接口各写一套：

- Schema 先行，类型放在 `src/main/resources/graphql/*.graphqls`，按领域拆文件，用 `extend type` 合并。
- 不把 JPA 实体直接返回给 GraphQL。查询和变更都走 View / Input。
- 写操作进 Service，加事务；关联字段用 `@BatchMapping` 批量加载。
- 业务失败用稳定的 `extensions.code`，不要把 SQL 或堆栈返回给调用方。
- 金额用十进制字符串，时间用 ISO-8601 字符串。

## 版本

| 项 | 选择 |
| --- | --- |
| JDK | 11，与父工程 `allst-db` 一致 |
| Spring Boot | 2.7.18 |
| GraphQL | `spring-boot-starter-graphql`（Spring for GraphQL 1.0） |
| 持久化 | Spring Data JPA + H2 内存库，重启后由样例数据重新写入 |
| 前端 | Vue 3 + Vite，直接 `fetch` 发 GraphQL，不引入 Apollo |

原先的草稿使用 `graphql-java-kickstart` 11，同时手写了 `GraphQLSchema`，又放了一份 `books.graphqls`，两边对不上，也没有数据库。Kickstart 这条线已经停止维护，Spring Boot 2.7 自带的官方 Starter 就是后续项目应采用的写法，所以草稿被替换掉了。

官方参考：

- [Spring for GraphQL 1.0 文档](https://docs.spring.io/spring-graphql/docs/1.0.x/reference/html/)
- [spring-graphql 仓库](https://github.com/spring-projects/spring-graphql)

## 演示业务

岸口货栈卖茶叶和器物。接口覆盖：

- 分类、商品、客户、地址、订单的增删改查
- 下单扣库存，取消订单把库存加回去
- 订单状态按固定顺序流转，并用订阅把变化推出去
