# 06 变更、校验与订单流转

变更都是 `Mutation`。控制器只做参数绑定，规则在 Service。

## 商品、分类、客户

创建和更新使用同一份 Input，更新是整单覆盖，不是补丁。没传的可选字段按空处理，例如商品说明。

删除是物理删除，但受上一篇里的引用约束。违反约束时 code 为 `CONFLICT` 或 `ILLEGAL_STATE`。

新建客户必须带第一条地址，对应 `CreateCustomerInput`。之后改客户资料用 `CustomerInput`，不加地址；地址用 `createAddress` / `deleteAddress`。新地址若标记为默认，会先清掉该客户其他地址的默认标记。

分类不能把上级设成自己，也不能挪到自己的下级下面。`CatalogService.resolveParent` 向上走最多 20 层。

## 下单

`createOrder` 在一个事务里完成：

1. 同一张订单里同一个商品只能出现一次，数量在客户端合并。
2. 地址必须属于该客户。
3. 商品必须是 `ON_SALE`，库存必须够。
4. 扣减库存，写入订单和明细。明细上的名称、单价是当时的快照。
5. 地址拼成 `省 + 市 + 详细地址` 记在订单上。
6. 事务提交之后才发布状态事件。提交失败时，订阅方不会收到这张订单。

订单号形如 `NO` + 时间 + 4 位随机数，列上有唯一约束。

## 状态

```
待支付 CREATED → 已支付 PAID → 已发货 SHIPPED → 已完成 COMPLETED
待支付、已支付 → 已取消 CANCELLED
```

其他跳跃会得到 `ILLEGAL_STATE`。`cancelOrder` 是走到 `CANCELLED` 的快捷方式。取消时把明细数量加回库存。已发货和已完成不能取消。

`deleteOrder` 只接受已取消的订单。柜台里取消和删除是两步，避免把“不做这单了”和“从库里抹掉”合成一次操作。
