# 05 查询、分页与过滤

入口是 `POST /graphql`，请求体：

```json
{
  "query": "query($id: ID!) { product(id: $id) { name price } }",
  "variables": { "id": "1" }
}
```

`ID` 在 Java 方法里是 `Long`，响应里仍是字符串。

## 分页

商品、客户、订单使用同一套 `PageInput`：

```graphql
products(filter: { keyword: "龙井", status: ON_SALE }, page: { page: 0, size: 8 }) {
  total
  page
  size
  totalPages
  content { id name price }
}
```

`page` 从 0 开始。`size` 缺省 10，小于 1 时按 1，大于 50 时按 50。排序固定为 `id` 降序，实现在 `PageRequests`。

Java 侧用一个 `Slice<T>` 承载分页结果。GraphQL 没有泛型，所以 Schema 里仍然分开写 `ProductPage`、`CustomerPage`、`OrderPage`，字段名保持一致。

分类数量少，`categories` 一次返回全部，不分页。树用 `parent` 和 `children` 取，客户端要多深由查询自己决定。

## 过滤

`ProductSpecs` 把 `ProductFilter` 转成 JPA Specification：

- `keyword` 匹配名称或说明，大小写不敏感，`%` 和 `_` 会转义
- `categoryId`、`status`、`minPrice`、`maxPrice` 都是可选的
- 条件之间是并且

订单列表可以按 `customerId` 和 `status` 过滤，规则在 `OrderSpecs`。

单个资源用 `product(id)`、`order(id)`、`orderByNo(orderNo)`。`health` 固定返回 `ok`，给前端判断柜台是否连上。
