# 06 搜索建议

## 场景

用户输入前几个字时，给出文章、地点或商品的补全。这是前缀补全，不是把全文检索的第一页拿来当建议。

## 为什么单独用 RestHighLevelClient

索引映射仍由 Spring Data 的 `@CompletionField` 生成，写入也走 `ElasticsearchRestTemplate`。Spring Data Elasticsearch 4.2 的 `SearchHits` 没有 suggest 结果，`NativeSearchQueryBuilder` 也不能表达 completion。因此补全查询使用工程里已经存在的 `RestHighLevelClient`，请求发到同一个 `https://127.0.0.1:9200`。

这个分工可以记成：mapping 和文档写入用 Spring Data，Spring Data 4.2 覆盖不到的 suggester 用官方高层客户端。

## 索引

索引名 `scenario_suggest`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| name、category | keyword | 展示名和分类 |
| weight | integer | 同时写入 completion 的权重，权重大的排在前面 |
| suggest | completion | 前缀索引。输入可以是名称加别名 |

completion 使用默认 `simple` 分析器。中文没有空格时，整段名称是一个 token，前缀匹配靠 token 开头，所以别名要单独放进 `inputs`。例如“故宫博物院”额外放入“故宫”，输入“故宫”才能命中。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/suggest/index/init` | 创建索引 |
| POST | `/scenario/suggest/seed` | 写入文章、地点、商品的补全词 |
| POST | `/scenario/suggest/terms` | 新增一条。`inputs` 是别名列表 |
| GET | `/scenario/suggest/complete` | 参数 `prefix`、`size`。size 最大 20 |

查询设置了 `skip_duplicates`，相同文本只返回一次。

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/suggest/seed
curl.exe "http://127.0.0.1:4565/scenario/suggest/complete?prefix=手机"
curl.exe "http://127.0.0.1:4565/scenario/suggest/complete?prefix=故宫"
```

新增：

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/suggest/terms -H "Content-Type: application/json" -d "{\"name\":\"西湖游船\",\"category\":\"地点\",\"weight\":5,\"inputs\":[\"西湖\"]}"
```

## 生产环境要注意

- completion 适合短词和明确的输入列表，不适合整篇正文。正文补全应先有词库或搜索历史。
- 权重来自点击或销量时，定期重建 suggest 字段，不要在查询时再排序一遍全文。
- 若要按分类过滤建议，给 `@CompletionField` 配置 context。样例没有开 context，分类只作为展示字段。
