# 07 电商分面检索

## 场景

商品搜索除了关键词，还要同时给出可选的类目、品牌和价格区间。选中一个品牌后，商品列表收窄，类目分面仍保留其他类目。选中一个类目后，品牌分面只统计该类目下的品牌，类目分面本身仍保留其他类目，方便改选。

这是在全文搜索和实时分析之外补上的常见场景。

## 索引

索引名 `scenario_product`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| title | text，IK | 相关度 |
| brand、category、tags | keyword | 分面和过滤 |
| price | double | 区间、统计、排序 |
| sales | integer | 默认排序 |
| onSale | boolean | 是否在售 |

## 查询规范

一次请求拆成三部分：

1. `query` 只放标题检索。没有关键词时是 `match_all`。聚合跟着 query 走。
2. `post_filter` 放品牌、类目、价格、是否在售。它只影响命中列表，不把其他分面过滤掉。Spring Data 4.2 里对应 `NativeSearchQueryBuilder.withFilter`。
3. 每个分面是一个 `filter` 聚合，里面套 terms 或 range。类目聚合包含品牌和价格条件，但不包含类目自身；品牌聚合同理。价格区间和价格统计不包含价格条件，这样滑块仍能看到整体价格分布。是否在售属于全局条件，三个分面都会带上。

价格区间固定为：100 以下、100-499、500-1999、2000 及以上。

排序：`priceAsc`、`priceDesc`、`sales`。没有关键词又没有指定排序时，按销量倒序。有关键词且未指定排序时，按相关度。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/product/index/init` | 创建索引 |
| POST | `/scenario/product/seed` | 写入 8 个商品 |
| POST | `/scenario/product/docs` | 新增或覆盖 |
| GET | `/scenario/product/search` | 参数 `q`、`brand`、`category`、`minPrice`、`maxPrice`、`onSale`、`sort`、`page`、`size` |

返回里 `hits` 是当前筛选下的商品，`categories`、`brands`、`priceRanges` 是分面，`minPrice`、`maxPrice`、`avgPrice` 来自价格统计。

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/product/seed
curl.exe "http://127.0.0.1:4565/scenario/product/search?q=手机"
curl.exe "http://127.0.0.1:4565/scenario/product/search?category=手机&sort=priceAsc"
curl.exe "http://127.0.0.1:4565/scenario/product/search?minPrice=100&maxPrice=1000&onSale=true"
```

用 `category=手机` 搜索时，命中只有两部手机，`brands` 只剩小米和华为；`categories` 仍保留图书、外设等类目。分面聚合会带上其他筛选，但排除自己这一维的筛选。

## 生产环境要注意

- 分面字段必须是 keyword。不要对中文标题做 terms。
- 分面桶数量要限制。样例每个 terms 最多 20 个。
- 属性很多时，把规格拆成 `nested`，避免颜色和尺码交叉污染。样例的标签是扁平 keyword，没有这个交叉问题。
- 价格统计受当前非价格条件影响。前端展示“全部商品的价格带”时，不要再把价格筛选放进这个统计。
