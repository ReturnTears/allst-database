# 03 地理数据应用

## 场景

门店、景点、设备需要回答三类问题：某个坐标附近有什么、一个矩形范围内有什么、哪些区域更密集。

## 索引

索引名 `scenario_place`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| name、address | text，IK | 名称和地址检索 |
| category、city | keyword | 精确过滤。样例分类是 `古迹`、`地标`、`公园` |
| location | geo_point | 距离、矩形、geohash 聚合 |
| rating | double | 展示用评分 |

写入接口不直接接收 `GeoPoint`。请求体使用 `lat`、`lon`，服务再组装坐标。读出来的 `location` 是 `{"lat":39.9,"lon":116.3}`。

## 查询规范

- 附近：`geo_distance` 过滤，再按 `geo_distance` 升序。返回里的 `distanceKm` 来自排序值。
- 矩形：`geo_bounding_box`。北纬必须大于南纬。
- 热力：`geohash_grid`。精度 1 到 8，默认 5，大约几公里一个格子。只返回格子和文档数。

名称关键词仍然走 `multi_match`，分类走 filter。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/geo/index/init` | 创建索引 |
| POST | `/scenario/geo/seed` | 写入北京、上海、杭州、广州、深圳的 11 个地点 |
| POST | `/scenario/geo/places` | 新增地点 |
| GET | `/scenario/geo/nearby` | 参数 `lat`、`lon`、`distanceKm`、`category`、`q`、`size` |
| GET | `/scenario/geo/bbox` | 参数 `topLat`、`leftLon`、`bottomLat`、`rightLon`、`category`、`size` |
| GET | `/scenario/geo/heatmap` | 参数 `category`、`precision` |

## 调用示例

天安门附近 2 公里：

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/geo/seed
curl.exe "http://127.0.0.1:4565/scenario/geo/nearby?lat=39.905489&lon=116.397631&distanceKm=2"
```

预期能看到故宫、天安门、国家博物馆，颐和园不在这个距离内。

北京城区矩形和热力：

```bat
curl.exe "http://127.0.0.1:4565/scenario/geo/bbox?topLat=40.05&leftLon=116.20&bottomLat=39.85&rightLon=116.50&category=古迹"
curl.exe "http://127.0.0.1:4565/scenario/geo/heatmap?precision=4"
```

新增地点：

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/geo/places -H "Content-Type: application/json" -d "{\"name\":\"景山公园\",\"category\":\"公园\",\"city\":\"北京\",\"address\":\"北京市东城区景山西街44号\",\"lat\":39.925,\"lon\":116.396,\"rating\":4.5}"
```

## 生产环境要注意

- 坐标统一用 WGS84，并在接口文档里写明。样例坐标只用于演示相对位置。
- 距离排序和分页一起用时，跨分片要保证 `geo_distance` 排序字段一致。
- 热力图精度过高会生成大量桶。对外接口限制精度，并对 `size` 设上限。样例上限是 100 个格子。
- 若要“城市内附近优先”，先用 `city` 做 filter，再做距离排序。
