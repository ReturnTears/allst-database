# 01 全文搜索

## 场景

文章、公告、知识库需要按关键词召回，同时按栏目、作者、标签和时间筛选，并在结果里标出命中的词。同一篇文章还可以找内容相近的其他文章。

适合：标题和正文都要参与打分的检索。

不适合：只按编号精确查找。那种需求用 `keyword` 的 term 查询即可，不必走全文打分。

## 索引

索引名 `scenario_article`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| title、summary、content | text，IK | 全文检索和高亮。标题权重 3，摘要 2，正文 1 |
| author、category、tags、status | keyword | 精确过滤。tags 是关键词数组 |
| publishTime | date | 时间范围和默认排序 |
| viewCount | integer | 预留排序 |

`status` 默认只查 `published`。传入 `status=all` 时不过滤状态。

## 查询规范

- 有关键词时用 `multi_match`，类型 `best_fields`。`phrase=true` 时改为 `phrase`，要求词序连续。
- 栏目、作者、标签、状态、时间放在 `bool.filter`，不参与打分。
- 没有关键词时按 `publishTime` 倒序。
- 标题和正文返回 `<em>` 高亮。正文最多两个 80 字片段。
- 相似文章使用 `more_like_this`，排除自身，只在已发布文档里找。样例数据较短，所以 `min_term_freq` 和 `min_doc_freq` 都是 1。语料变大后应提高这两个值。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/fulltext/index/init` | 创建索引。返回 true 表示这次新建 |
| POST | `/scenario/fulltext/seed` | 写入 6 篇样例文章 |
| POST | `/scenario/fulltext/docs` | 新增或覆盖一篇 |
| GET | `/scenario/fulltext/docs/{id}` | 按 id 读取 |
| DELETE | `/scenario/fulltext/docs/{id}` | 删除 |
| GET | `/scenario/fulltext/search` | 检索 |
| GET | `/scenario/fulltext/docs/{id}/similar` | 相似文章 |

检索参数：`q`、`category`、`author`、`tag`、`status`、`from`、`to`、`phrase`、`page`、`size`。

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/fulltext/seed
curl.exe "http://127.0.0.1:4565/scenario/fulltext/search?q=Elasticsearch&category=搜索"
curl.exe "http://127.0.0.1:4565/scenario/fulltext/search?q=索引设计&phrase=true"
curl.exe "http://127.0.0.1:4565/scenario/fulltext/docs/article-1/similar?size=3"
```

新增文章：

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/fulltext/docs -H "Content-Type: application/json" -d "{\"title\":\"索引别名切换\",\"summary\":\"重建索引时对外仍使用别名\",\"content\":\"先写新索引，再原子切换别名。\",\"author\":\"林知夏\",\"category\":\"工程\",\"tags\":[\"别名\"],\"status\":\"published\"}"
```

## 生产环境要注意

- 高亮字段必须能从 `_source` 取到原文，不要把大字段设成不存储。
- `track_total_hits` 在样例里打开了。数据量大时可以关闭精确总数，或只在第一页统计。
- 相似推荐若要稳定，给正文单独建一个用于 `more_like_this` 的字段，并限制 `max_query_terms`。
