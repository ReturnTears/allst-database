# 04 日志与事件数据分析

## 场景

应用日志进入 Elasticsearch 后，需要按级别、服务、事件和时间检索原文，并给出错误率、耗时分位数和趋势。这是日志分析，不是把日志文件再算一遍。

## 索引

索引名 `scenario_app_log`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| message | text，IK | 原文检索 |
| level、service、host、traceId、event | keyword | 过滤和聚合 |
| timestamp | date | 窗口和趋势 |
| costMs、statusCode | integer | 耗时分位数、状态码 |

`message` 和 `event` 必须分开。全文聚合会得到无法控制的词项；事件码才能做 Top N。样例事件有 `REQUEST`、`PAY_FAIL`、`DB_SLOW`。级别使用 `INFO`、`WARN`、`ERROR`。

## 查询规范

检索：

- `message` 使用 match
- level、service、event 使用 term filter
- 时间默认最近 1 天，按 `timestamp` 倒序

报表一次查询完成：

- `filter` 聚合统计 `level=ERROR`，错误率 = 错误数 / 总数
- terms：级别、服务、事件
- `percentiles` 取 `costMs` 的 50、95、99
- `date_histogram` 看趋势。短窗口按小时，长窗口按天

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/log/index/init` | 创建索引 |
| POST | `/scenario/log/seed` | 写入 36 条最近日志，其中包含错误和慢查询 |
| POST | `/scenario/log/events` | 追加一条日志并刷新 |
| GET | `/scenario/log/search` | 参数 `q`、`level`、`service`、`event`、`from`、`to`、`page`、`size` |
| GET | `/scenario/log/report` | 参数 `service`、`from`、`to`、`interval` |

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/log/seed
curl.exe "http://127.0.0.1:4565/scenario/log/search?q=超时&level=ERROR"
curl.exe "http://127.0.0.1:4565/scenario/log/report?service=payment&interval=hour"
```

追加一条错误日志后再看报表，错误数会增加：

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/log/events -H "Content-Type: application/json" -d "{\"level\":\"ERROR\",\"service\":\"payment\",\"host\":\"host-1\",\"traceId\":\"trace-new\",\"event\":\"PAY_FAIL\",\"message\":\"支付渠道返回超时\",\"costMs\":1200,\"statusCode\":504}"
```

## 生产环境要注意

- 日志索引按天滚动，检索走别名。固定索引只适合这个样例。
- 原文不要拿去做 terms。需要统计的错误类型在采集时写成 `event`。
- 分位数是近似值。对比延迟时固定算法和压缩参数，不要混用不同版本的结果。
- 检索默认带时间范围。没有时间边界的全文查询会扫全部历史分片。
