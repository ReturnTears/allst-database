# 05 安全信息和事件管理

## 场景

安全设备和应用把登录、网络访问、权限变更写成统一事件。分析人员要能检索原始事件，也要能在一个时间窗口里看到超过阈值的主体。

这个场景只做检测和统计：登录失败过多、短时间访问的目的端口过多、权限变更过多。不提供入侵步骤。

字段是扁平的，便于 Spring Data 映射。生产事件建议再对齐 Elastic Common Schema，例如把 `srcIp` 收成 `source.ip`。

## 索引

索引名 `scenario_security_event`。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| eventTime | date | 窗口和趋势 |
| eventType、severity、srcIp、destIp、userName、host、action、outcome、ruleId | keyword | 过滤与聚合 |
| srcPort、destPort | integer | 端口。目的端口参与去重 |
| message | text，IK | 事件描述检索 |

样例事件类型：

- `login_failure`、`login_success`
- `port_scan`
- `privilege_change`
- `malware_detect`

## 检测规则

规则不写进查询脚本，而是先聚合、再由 `SiemRuleEngine` 判断。这样阈值变更不用改查询，也能不连集群做测试。

| 规则 | 聚合 | 默认阈值 |
| --- | --- | --- |
| BRUTE_FORCE | `eventType=login_failure`，按 `srcIp` 计数 | 5 |
| PORT_SCAN | `eventType=port_scan`，按 `srcIp` 对 `destPort` 做 cardinality | 6 |
| PRIVILEGE_CHANGE | `eventType=privilege_change`，按 `userName` 计数 | 3 |

端口数放在桶的 `metric` 上。`NamedCount.signal()` 优先读 `metric`，没有指标时用文档数。阈值传 0 或空时使用默认值。

样例数据会同时触发三条规则：`198.51.100.23` 有 6 次登录失败，`203.0.113.10` 访问了 8 个目的端口，`alice` 有 3 次权限变更。`carol` 的成功登录和 `dave` 的单次文件检测不会触发这三条规则。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scenario/siem/index/init` | 创建索引 |
| POST | `/scenario/siem/seed` | 写入可触发规则的样例事件 |
| POST | `/scenario/siem/events` | 接入一条事件并刷新 |
| GET | `/scenario/siem/search` | 原始事件。参数 `q`、`eventType`、`severity`、`srcIp`、`userName`、`from`、`to`、`page`、`size` |
| GET | `/scenario/siem/dashboard` | 分布、趋势和告警。另有 `bruteForceThreshold`、`portScanThreshold`、`privilegeThreshold` |

默认统计窗口是最近 1 天。

## 调用示例

```bat
curl.exe -X POST http://127.0.0.1:4565/scenario/siem/seed
curl.exe "http://127.0.0.1:4565/scenario/siem/dashboard"
curl.exe "http://127.0.0.1:4565/scenario/siem/search?eventType=login_failure&srcIp=198.51.100.23"
curl.exe "http://127.0.0.1:4565/scenario/siem/dashboard?bruteForceThreshold=10"
```

把登录失败阈值调到 10 后，样例里的 6 次失败不再产生 `BRUTE_FORCE`。

## 生产环境要注意

- 告警要有抑制和归并。同一 IP 在窗口内只生成一条，而不是每个事件一条。当前实现就是按主体聚合后的一条告警。
- 检测查询和原始检索分开。大盘只取聚合，事件明细走 search。
- 规则阈值放到配置或规则表，不要散落在控制器里。这里用请求参数是为了方便对照样例。
- 接入层负责把不同设备的日志规范成同一套 `eventType`。检测逻辑不解析各厂商原文。
